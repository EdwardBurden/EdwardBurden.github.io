After getting some other small projects under my belt, I wanted to try out a 2D renderer that would also let me get to grips with how windows in Windows are made and managed. The idea is to eventually have an application that can seamlessly switch between renderers like Direct2D, Vulkan and OpenGL.

The main aim of this project is to have fun learning how to render things with Direct2D, draw some text, and replicate a very basic, trimmed down version of the Unity hierarchy structure, with an interactive way to view the hierarchy.

I used [Module 3 of Microsoft's Learn Win32 series](https://learn.microsoft.com/en-us/windows/win32/learnwin32/module-3---windows-graphics) as my starting point. It walks through the Windows graphics architecture and gets a first Direct2D program drawing in a window. Once that was working, I decided to extend the starter project by setting up the structure around it.

Direct2D only draws shapes, so layout, hit testing and element ownership have to be built by hand. This post covers the scene node tree at the core of my UI framework.

## The Node

Everything on screen is a Node: a RectTransform, an optional Graphic and Collider, and a list of children.

I very quickly started making a way too complicated ECS, but decided it was unnecessary and pulled it back. After all, my UI framework just needs some simple visuals, so having hardcoded optional pointers to base classes of "components" was good enough in this case.

```cpp
class Node
{
public:
    const wchar_t* DebugName;
    RectTransform Transform;
    Graphic* Graphic;
    Collider* Collider;
    Node* Parent;
    std::vector<Node*> Children;

    Node(const Node& node) = delete;
    Node& operator=(const Node& node) = delete;

    Node(const wchar_t* name, Node* parent) : DebugName(name), Parent(parent), Graphic(nullptr), Collider(nullptr)
    {
        if (Parent == nullptr)
            return;

        Parent->Children.push_back(this);
    }

    ~Node()
    {
        delete Graphic;
        delete Collider;

        for (auto child : Children)
        {
            delete child;
        }
        Children.clear();
    }
};
```

Parents own their children: a new node registers itself with its parent, and deleting a node deletes its whole subtree, so only the root is deleted by hand. Copying is disabled because a copy would free the same objects twice.

## Laying out the tree

A node's rectangle depends on its parent's, so the tree is processed top-down with a queue of node and parent-rect pairs, starting from the window rectangle.

```cpp
void Scene::RecalculateTree(RECT window)
{
    // Create Queue of nodes to process along with their parentRect.
    std::queue<std::pair<UI::Node*, D2D1_RECT_F>> layers;
    D2D1_RECT_F parent = { window.left, window.top, window.right, window.bottom };
    // Place the Root and window rect as the first node to process.
    layers.push({ m_root, parent });

    // Each node in the tree will be processed by depth layer in the tree first.
    while (!layers.empty())
    {
        // Copy the front entry out before popping it.
        auto [node, parentRect] = layers.front();
        layers.pop();

        // Calculate this node's rect, then queue each child along with it.
        D2D1_RECT_F result = node->Transform.CalculateRect(parentRect);
        for (auto child : node->Children)
        {
            layers.push({ child, result });
        }
    }
}
```

The binding must copy rather than use auto&, because pop() destroys the element and a reference would dangle.

Looking at this code, you can see a very obvious problem that I am hoping to fix properly later: it always recalculates the whole structure. Among other features, I would like to add a "dirty" flag per object, with a way for the tree to be recalculated only from the nodes that have changed, and down from there.

That said, it works and for now it keeps the project simple. I'm not aiming for performance at this stage.

```cpp
UI::Node* Scene::SearchNodeForCollision(UI::Node* node, D2D1_POINT_2F point)
{
    if (node == nullptr)
        return nullptr;

    // Get reverse order of the way children are drawn.
    for (std::vector<UI::Node*>::reverse_iterator it = node->Children.rbegin(); it != node->Children.rend(); ++it)
    {
        // Recursively search for collider that passes the hit test.
        UI::Node* nodeHit = SearchNodeForCollision(*it, point);
        if (nodeHit != nullptr)
            return nodeHit;
    }

    // Check point is in the collider's area.
    if (node->Collider != nullptr && node->Collider->HitTest(node->Transform, point))
        return node;

    return nullptr;
}
```

</div>
</div>

Children are tested before their parent, so a button wins over the panel beneath it. Siblings are tested in reverse draw order, so the node painted on top wins. Nodes without a Collider are never hit.

For now the collider is just a simple box collider test. Because of the setup, though, the collider code can have derived classes for different shapes: for text, meaning you could click on specific letters, or even textures and meshes for specific behaviours.

## Driving it every frame

```cpp
void App::RenderLoop()
{
    RECT rect;
    GetClientRect(m_window->GetWindowHandle(), &rect);
    m_scene->m_root->Transform.SizeDelta.x = m_showDebug ? -200 : 0;
    m_scene->RecalculateTree(rect);

    m_window->BeginWindowPaint();
    m_renderer->BeginRender(m_window->GetWindowHandle());
    m_renderer->RenderNode(m_scene->m_root);

    if (m_showDebug)
    {
        Debug_DrawHierarchy();
        Debug_DrawGizmos();
    }

    m_renderer->EndRender();
    m_window->EndWindowPaint();
}
```
